# 04 · 配乐与卡点

> 标杆样片的配乐实测约 112 BPM（`fit_song.py` 量出 112.8，字幕换句和小节线平均差 0.1 秒），一小节约 2.13 秒，**一句字幕正好一小节**——节奏感就是这么来的。
> 所以这里的规矩是反过来的：先定速度，再按"一句一小节"排字幕，画面的每一次变化都落在小节线（重拍）上。

## 三种配乐，开工前问一句

| 用户说 | 怎么做 | 能不能直接发 |
|---|---|---|
| 没想好 / 交给你 | **合成配乐**（默认）：按片子结构自动作曲，选一种风格 | 能，自己合成的，没有版权问题 |
| 我有能商用的歌（自己做的、买了授权、免版税曲库下载的） | **用自己的歌**：`fit_song.py` 量节拍、挑段落，片子卡到歌的重拍上 | 能（授权在他手上） |
| 想用抖音 / 剪映里的热歌 | **平台曲库**：出片时自动多出一版「配平台音乐用」（只有卡点音效），他在 App 里加歌 | 只能在 App 里加；把热歌合进视频文件再发，会被判版权、静音或限流 |

答案写进 brief 的 `music`（可不写）：`{"style": "warm"}` 或 `{"song": "歌的路径"}`。**来路不明的 mp3、平台热歌下载下来的文件，一律不合进文件**；标杆样片那首 BGM 来源不明，不能放进技能，也不要替用户用。

## 合成配乐：五种风格

`scripts/make_cues.mjs` 读 film.json 自动作曲（`build.sh` 会自己跑），风格写在 film.json 的 `music.style`（brief 写了就照 brief）；不写按速度选：128 → 紧张，100 → 温暖，其他 → 律动。

| style | 叫法 | 和弦 | 节奏 | 适合 |
|---|---|---|---|---|
| `drive` | 律动（默认） | Am F C G | 八分音符拨弦，四拍底鼓 + 二四拍拍手 | 和标杆样片同一路子：讲道理、讲出路 |
| `tension` | 紧张 | Am Am F E（和声小调） | 十六分音符镲，八分音符低音往前推 | 讲危机、倒计时、价格战 |
| `warm` | 温暖 | C G Am F（大调） | 铃声琶音，一三拍底鼓，二四拍木鱼 | 讲成长、陪伴、宝妈 / 学生的故事 |
| `lofi` | 轻松 | Dm7 G7 Cmaj7 Am7 | 摇摆八分音符，木鱼当军鼓 | 聊天感、日常、复盘 |
| `doc` | 纪录片 | Am F C G（钢琴柱式和弦） | 每小节两记钢琴，很轻的打击，不抽吸 | 讲得严肃一点：我的弯路、观点片、复盘 |

**Vibe 知识大赏的两种配乐路子**（11-18 查过）：竖屏卡点系列是约 112 BPM 的电子律动（对应 `drive`）；横屏讲概念系列是 76–78 BPM 的小调钢琴加长音铺底（有人从 8 条原片逆向拆过，对应 `doc`，我们保持一句一小节的速度，只换音色和织体）。它们用的都是现成的歌，项目本身只合成音效、不生成 BGM——所以别想着把原片的 BGM 拿来用，在 App 曲库里选才是正路。

**听感对标**（11-18）：拿一首知识类电子 BGM 做参照逐项量过——它的低音、低中频、中频 86–97% 的时间都铺满，我们原来只有 22–41%（一下一下的拨弦，像玩具）。
现在每种风格都有一层**厚和弦**（几个略微走音的锯齿波叠在一起）和**持续贝斯**，每拍底鼓时和弦、贝斯让一下再涨回来（抽吸，律动感和卡点感都来自它）；
律动风格混完后低音 / 低中 / 中频铺满 89% / 94% / 98%，和参照几乎重合。紧张、律动抽吸重；温暖、轻松抽吸轻、和弦暗。

不管哪种风格，都跟着片子的结构走：

| 片子里 | 配乐里 |
|---|---|
| 每一章 | 换一个和弦：厚和弦 + 持续贝斯铺底，每拍抽吸一次 |
| 第一章（钩子） | 第一帧一记 boom，每小节第一拍一下轻底鼓，只有琶音和镲，留空间给第一句字幕 |
| 第二章起 | 整套鼓 + 低音进来 |
| 反转那一章（`"turn": true`，不写就是倒数第二章） | 它前一小节撤掉鼓和贝斯，只剩和弦悬着 + 一个上滑音；反转落在重拍上全编制回来 + boom；**从反转起叠一层高八度和弦、镲变密、加一条旋律**，像进了副歌 |
| 盖章（`shot.stamp`） | 砸章那一拍一记低沉的"咚" |
| 每句字幕起点 / 每章起点 | 一声很轻的 tick / 一声 drop，前面一个短 whoosh |
| 片名、最后一句 | boom；最后一句再加一声 bell |

合成器是 `scripts/score.mjs`（零依赖、同样的输入永远出同样的文件，来源见 `LICENSE-THIRD-PARTY.md`）。

## 用自己的歌：`fit_song.py`

```bash
python3 scripts/fit_song.py <工程> <歌.mp3> --licensed      # 一首：量速度、挑段落、改好 film.json
python3 scripts/fit_song.py <工程> <放歌的文件夹> --licensed  # 选歌：逐首分析，按「节拍稳 + 速度接近 112 + 反转处歌变强」排名，用第一名
python3 scripts/fit_song.py <歌或文件夹>                      # 只看分析，不改文件
bash scripts/build.sh <工程>                                  # 用这首歌代替合成配乐，卡点音效叠在上面
```

- 只要 ffmpeg，不装别的库；一首两分钟的歌分析约 3 秒。
- 起音按 6 个频段分别看（底鼓、和弦、镲各自的变化加起来）：商业成品歌压得很满，只看总音量时鼓点被埋掉，节拍稳的歌也会被判成"不稳"（11-18 用一首知识类 BGM 实测踩过）。
- 它做的事：量速度（偏向 90–140 BPM）→ 找每小节第一拍（换和弦的地方 + 底鼓最重的那一拍）→ 挑一段：整段够响、反转那句正好落在歌变强的地方、从 4 小节乐句开头起、避开对不齐的小节（中途变速、自由节奏的地方）→ 改 film.json 的 `bpm` 和 `music`（`song` `start`），也写进 brief 的 `music`。
- 歌的速度和原来不一样，句数也要跟着变（30 秒在 120 BPM 下是 15 句）：它会提醒重跑 `ds_make.py`，`ds_make.py` 按歌的速度重新排句数，写完自动再对一次歌。
- **节拍不稳**（现场录音、自由节奏、没有鼓）它会说，建议换一首有稳定鼓点的。
- **出片后听一下**：字幕换句那一下应该是一小节里最重的那一拍。落在反拍上（检测把第三拍当成了第一拍，四拍鼓一样重的歌偶尔会这样），加 `--shift=2`（或 1、3）重跑 `fit_song.py`，再 `build.sh`。
- `--licensed` 是用户确认能商用。没确认就不加，脚本会停下解释为什么。

## 平台曲库：「配平台音乐用」那一版

`build.sh` 每次出片都多出两个文件：

- `renders/<片名>-配平台音乐用.mp4`：只有卡点音效（换章、片名、反转、盖章、片尾），没有音乐，响度 −18 LUFS，留出空间给 App 里加的歌；
- `renders/发布说明.txt`：速度、一小节几秒、第一拍在第 0 秒，按风格给出去曲库搜什么词，怎么在剪映 / 抖音里对齐（选中音乐点「踩点」看节拍；原声留 50%–70%）。

说明里**不写具体歌名**：平台热歌每周都在变，写死会过时，也容易让人以为能把歌合进文件里。

## 想要更强的作曲（另装，可选）

合成配乐是"按结构自动编"，不是一首有记忆点的歌。想要真正作曲，GitHub 上这两个和本技能路子最近（都是 MIT，都不用音乐生成模型、不涉及版权）：

| 项目 | 做法 | 什么时候用 |
|---|---|---|
| `owoevan-dev/music-skill` | 让模型逐个音符写曲，出 MP3 + MIDI + 分轨，能改任何一个音再出 | 想要一首有旋律、有记忆点的原创 BGM，愿意多花模型用量 |
| `whyubel1eve/promo-bgm-skill` | 一首曲子写成一份 JSON（段落、和弦、鼓的档位），纯代码合成，同一份 JSON 永远出同一个文件 | 想手动调段落和编曲 |

做出来的曲子当成"自己的歌"，用 `fit_song.py` 卡到片子上。用 Suno 这类生成服务做的歌，先看清它的商用条款。

## 混音规格

- 响度 −14 LUFS、真峰 ≤ −1.2 dBFS（`build.sh` 混完实测，按差多少修正，真峰还超就再压一次；用歌时不先压峰值，多留 1 dB）；
- 文件里写入不可见的 AI 生成标记（`comment` / `description` 元数据），发布时提醒用户打开平台的"AI 生成"声明；
- 没有人声。
