# 05 · 检查表

## 机器（`scripts/build.sh` 第一步自动跑 `check_film.py`，有错误不渲）

| 检查 | 规矩 | 为什么 |
|---|---|---|
| 句数 | = 时长 ÷ 一小节（112 BPM：30 秒 14 句 / 60 秒 28 / 90 秒 42），误差 ±1 | 一句一小节才卡得上拍 |
| 字幕 | 不带标点；≤ 16 字；高亮词 ≤ 2 个且在字幕里 | 一眼读完；标杆样片就是这样 |
| 结构 | 每章第一句开新镜；件名认识；必填字段齐；列表个数在范围内 | 件只认这些字段，缺了画不出来 |
| 出处 | 屏上有数字的镜必须有 note；brief 标了 `example` 的，note 必须写「示例」或「示意」 | 不编数字、不冒充真实数据 |
| 联系方式 | 微信 / QQ / 二维码 / 私信我 … 一律报错 | 平台限流，也是红线 |
| 收入承诺 | 月入 / 稳赚 / 回本 / 暴富 … 一律报错 | 广告法、平台规则 |
| 内部用语 | 「不含联系方式」「访谈」「作者本人账目」「分镜」「提示词」… 一律报错 | 写给我们自己看的话不能上屏 |
| brief 禁用词 | brief.banned 里的词一律报错 | 用户自己定的 |
| 绝对化用语 | 最好 / 第一 / 唯一 / 100% …（警告） | 观点片偶尔要用，自己判断 |
| 开头和结尾 | 第一镜不是钩子类、结尾没有"主页 / 合集 / 评论"（警告） | 引流片的两头 |

画面层面的越界、字压字、字幕溢出由件本身管住（件只把东西画在 y 400–1400，字幕自动缩字号）；新写的件要自己截图看。
渲完 `build.sh` 打印实测响度和真峰，并出一张 16 格拼图 `review/sheet.jpg`。

## 人（看拼图和成片，2 分钟）

1. **遮住字幕看拼图**：每一章在演什么，猜得出来吗？
2. **只读字幕**：是不是一段通顺、有落点的话？
3. **手机外放听一遍**：哪一句想划走？那一句就是要改的。

## 交付

| 项 | 标准 |
|---|---|
| 成片 | `renders/<片名>.mp4`，1080×1920、30fps、−14 LUFS |
| 事实表 | 每个数字带出处（后台截图 / 规则链接 / 用户原话）；example 的片子写明"示例，不能发布" |
| 标题与话题 | 标题 ≤ 20 字 + 3–5 个话题，不用绝对化用语 |
| 记录 | 这条片的目标（引流到哪）、预计表现，发布 3 天后回填真实数据 |
| 提醒 | 发布时打开平台的"AI 生成内容"声明 |
