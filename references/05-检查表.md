# 05 · 检查表

## 机器（`scripts/build.sh` 第一步自动跑 `check_film.py`，有错误不渲）

| 检查 | 规矩 | 为什么 |
|---|---|---|
| 句数 | = 时长 ÷ 一小节（112.8 BPM：30 秒 14 句 / 60 秒 28 / 90 秒 42），误差 ±1；报错会列出各章几句、差几句 | 一句一小节才卡得上拍；弱模型自己数不清 |
| 字幕 | 不带标点；≤ 16 字；高亮词 ≤ 2 个且在字幕里 | 一眼读完；标杆样片就是这样 |
| 结构 | 每章有画面（章上的 shot，或第一句的 shot）；件名认识；必填字段齐；列表个数在范围内 | 件只认这些字段，缺了画不出来 |
| 出处 | 屏上有数字的镜必须有 note；brief 标了 `example` 的，note 必须写「示例」或「示意」 | 不编数字、不冒充真实数据 |
| 数字来源 | 屏上大于 10 的数要在 brief 的 pain / proof / audience 里找得到（"两百""两万""三千五"这类中文数也认）；从 brief 算出来的 note 写「按 … 算」，示意的写「示意」（只警告）；报错会写出是哪个字段 | 弱模型最常见的毛病就是编数（实测：把"几十份简历"编成 30 / 50 / 80） |
| 画面换得勤不勤 | 全片画面数 ≤ 句数的一半（报错）；一章只有 1 句、超过 5 句、没写 key（警告） | 标杆样片一个画面撑 3.5 句；一句一换像幻灯片，观众记不住 |
| 编的经历 | 字幕里出现 brief 没提的被裁、厂子、房贷、孩子这类经历（报错） | 例句是按「被裁之后」写的，别的题目最容易被带偏 |
| 凑巧算得出的数 | brief 里没有、但能用 brief 的数加减乘除凑出来的数：真实片要在 note 写「按 … 算」（报错） | 7 = 8 − 1 这种巧合会把编出来的数放过去 |
| 算账、岔路、横条 | ledger 只算钱；岔路点亮的不能是死路（全是死路写 pick: -1）；横条的数要是字幕说到的（报错） | 11-17 / 11-18 实测模型最常写偏的三处 |
| 发布文案 | post 的标题 ≤ 30 字、3–5 个话题；联系方式、收入承诺照样拦 | 发布标题和字幕一样是"屏外的字幕" |
| 画面会不会动 | 画面不动的句子（一镜的句子比件能变的次数多）≤ 1/5，只给提问、结论；说了数的句子一定要动（报错） | 说了数画面上没有，观众对不上；全片老不动会以为卡了 |
| 联系方式和诱导话术 | 微信 / QQ / 二维码 / 私信我 / 扣1 / 领资料 / 私我 … 一律报错 | 平台限流，也是红线（实测：看图评审会建议"评论区扣1领清单"） |
| 收入承诺 | 月入 / 稳赚 / 回本 / 暴富 … 一律报错 | 广告法、平台规则 |
| 内部用语 | 「不含联系方式」「访谈」「作者本人账目」「分镜」「提示词」… 一律报错 | 写给我们自己看的话不能上屏 |
| brief 禁用词 | brief.banned 里的词一律报错 | 用户自己定的 |
| 绝对化用语 | 最好 / 第一 / 唯一 / 100% …（警告） | 观点片偶尔要用，自己判断 |
| 开头和结尾 | 第一镜不是钩子类、结尾没有"主页 / 合集 / 评论"（警告） | 引流片的两头 |

画面层面的越界、字压字、字幕溢出由件本身管住（件只把东西画在 y 400–1400，字幕自动缩字号）；新写的件要自己截图看。
渲完 `build.sh` 打印实测响度和真峰，并出一张 16 格拼图 `review/sheet.jpg`。

## 人（看拼图和成片，2 分钟）

1. **遮住字幕看拼图**：每一章在演什么，猜得出来吗？
2. **只读字幕**：是不是一段通顺、有落点的话？
3. **手机外放听一遍**：哪一句想划走？那一句就是要改的。

## 交付

| 项 | 标准 |
|---|---|
| 成片 | `renders/<片名>.mp4`，1080×1920、30fps、−14 LUFS |
| 事实表 | 每个数字带出处（后台截图 / 规则链接 / 用户原话）；example 的片子写明"示例，不能发布" |
| 标题与话题 | 标题 ≤ 20 字 + 3–5 个话题，不用绝对化用语 |
| 记录 | 这条片的目标（引流到哪）、预计表现，发布 3 天后回填真实数据 |
| 提醒 | 发布时打开平台的"AI 生成内容"声明 |
